# ADR-008 — Qualify a bounded Genesis build patch

Status: locally implemented and Windows/Linux native-qualified after review, 2026-10-29. Supersedes the earlier decision to stop at the upstream graph defect, for this repository's packaged build only. Risk MEDIUM; complexity C-2.

The user asked to continue implementation. The exact upstream build remains unable to qualify native transaction graph ranking: the transaction memory/recovery path inserts support edges without refreshing native K-Impact. The public-main source checked again at `a14b6ad498d738e7a2343c901fff2b958035eba9` retains that defect.

Keep the previously tested upstream source pin and carry a small reviewable build patch under `infra/genesis`. Refresh affected native node impacts after applying a transaction's graph changes, including the previous target of a replaced edge and every upserted node. The latter is unconditional: a node that lost its last incoming edge must not regain `INITIAL_IMPACT` when updated. Run the same real BGE-M3 REST fixture before and after the change, with forced-process restart assertions. This changes the engine's native computation; the application must never manufacture graph scores.

Expose the packaged source commit and patch profile through the authenticated version response. Require that build identity in the application before publication/readiness; the package version alone cannot distinguish the failing upstream binary. Also issue the read-only `POST /v1/query` probe because version and collection metadata remain available while storage requires recovery; the native query path calls `ensure_readable` before scanning. The identity is deployment metadata, not cryptographic attestation. Source, patch and measured binary/image hashes provide the provenance record.

Readiness inspects all public active pointers, including failed or revision-mismatched generations that public retrieval excludes. It requires active state, canonical revision equality, the configured embedding model/dimension, and valid native collection coverage. Search rejects any active embedding configuration mismatch before embedding rather than returning an apparently successful empty result.

No upstream checkout, branch or release is changed. This build has a maintenance cost: every upstream update must reapply/review the patch and repeat native qualification. Rollback selects the unpatched source image and holds publication; PostgreSQL remains canonical. Physical deletion and the previously blocked volume-restore exercise remain separate unresolved gates.

Acceptance for this slice: failing original graph/restart assertions; passing patched native TH/EN graph-ablation/restart; native transaction regression tests; unpatched runtime denied; real PostgreSQL outbox activation, replay and revocation against the qualified engine; production profile data remains unapproved. The worker currently supplies one incoming `HAS_CHUNK` edge per chunk, so its graph scores are equal; the differential synthetic graph fixture does not prove an end-user relevance improvement.
